```scala
  case Compensated(receipt: CompensationReceipt)
```

特别是：

```text
Unknown
```

---

例如：

```text

```

这不是：

```text

```

应该：

```text
Unknown
```

然后：

```scala
trait ReconciliationPolicy:
  def reconcile(
    intent: EffectIntent,
    attempt: EffectAttempt
  ): IO[ReconciliationError, ReconciliationResult]
```

结果：

```text

ConfirmedFailed
StillUnknown
```

只有：

```text
ConfirmedFailed
```

才考虑安全 retry。

# 三十三、你可以直接把这一段作为 Codex/Cursor 的总约束

核心要求不是“实现越多越好”，而是：

```text
You are evolving zyblw-agent into a model-native,
ZIO-native durable Agent Control Runtime.

Do NOT redesign AgentKernel unless a runtime invariant
cannot be represented by existing semantics.

Do NOT introduce PlannerAgent, ReflectionAgent,
SupervisorAgent, SwarmEngine, or model-specific
reasoning patterns into the kernel.

The architecture must separate:

1. Agent capability semantics
2. Capability implementation
3. Execution placement
4. Model inference policy
5. Durable runtime invariants
6. Business side effects

AgentDefinition declares WHAT capabilities are required.

AgentCompiler resolves those requirements.

CapabilityResolver decides HOW capabilities are fulfilled:

- ModelNative
- RuntimeNative
- RemoteSandbox
- GovernedExternal

Model-specific capabilities must stay outside AgentKernel.

High-risk business operations must never become ModelNative.

Existing RuntimeExtensions remain low-level typed runtime
extension points; Capability is a higher-level composition unit,
not a replacement universal plugin system.

ZLayer remains the host dependency mechanism.
Do not build a string-based service locator.

CompositionManifest is the authoritative compiled composition.
Its fingerprint is only a hash of that manifest.

All model routing must be capability-aware, cost-aware and
deterministic first. Prefer cheap models and escalate based on
observable validators, not model self-reported confidence.

All external side effects must support explicit outcomes:
Succeeded, Failed, Unknown, Compensated.

Unknown outcomes must reconcile external reality before retry.

Every architectural change must include tests and preserve:
- durable recovery
- authorization invariants
- lease/fencing correctness
- context authority
- stable kernel semantics
- provider neutrality
```

这一段我认为非常适合作为所有阶段 Prompt 的固定 header。

后面每一阶段只追加：

```text
Now implement Phase 2: Capability Plane.
```

这种方式。

## 最终的开发优先级

如果让我亲自给 Codex 排开发顺序，我只会按下面这一条序列推进，**前一个阶段没有绿，不进入下一个阶段**：

1. **恢复当前 HEAD 全绿，并固定 Kernel architecture contract。**
2. **实现 Capability / CapabilityGraph / AgentCompiler，保留 RuntimeExtensions 作为底层。**
3. **加入 ExecutionPlacement，并建立不可降低安全等级的规则。**
4. **完善 ModelCapabilityMatrix + Reasoning / Cache / Native Tools / Agent execution mode。**
5. **把 ModelRouter 升成 deterministic `InferencePolicy + EscalationPolicy`，优先低价模型，失败后有依据地升级。**
6. **建立 `CompositionManifest → fingerprint → structured drift`。**
7. **真正接入 RuntimeDriver，并用 TCMResearchAgent + AmazonOpsAgent 做端到端验证。**
8. **时间允许再做 ChildRun / Handoff / Join，不做 Multi-Agent Pattern Engine。**
9. **最后补齐 `EffectOutcome.Unknown + Reconciliation`，把现实世界副作用可靠性做成招牌能力。**
10. **随后进入一段 feature freeze：跑长时间 soak、DB failover、真实业务 Eval、CostPerSuccess、API 稳定性和文档，而不是继续追新概念。**

这一次如果执行得好，我认为会比“再添加十几个 Agent 功能”有价值很多。

因为它解决的是 zyblw-agent 最关键的长期问题：

> **既能让今天便宜的 Qwen / DeepSeek 在强 Runtime 加持下承担大量实际业务，又能让未来更强模型出现后自然接管更多认知能力，而不会把 zyblw-agent 本身淘汰。**

最终你不是在和 GPT、Gemini、Qwen、DeepSeek 竞争谁更聪明。

你是在为它们建设一个稳定的“操作系统”。

而 **Capability Plane + Execution Placement + Inference Policy + CompositionManifest + Stable Kernel + Durable Control**，就是我认为接下来这几天最值得真正落到代码里的那一层。
