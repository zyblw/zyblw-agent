# 确定性质量流水线

用于长任务、重要交付或已经授权的多 Agent 协作；普通单模块修复走短路径。

## 先使用确定性工具

格式交给 scalafmt；类型交给编译器；文本搜索用 rg，语义定位可用现有 IDE 索引。需要批量转换时用可复现脚本并验证不变量，不为一次小编辑强制增加永久脚本。
Metals/Bloop 只在实际索引故障时修复，不在每次修改后重新导入构建。

## Green Gate 的适用范围

完成改动后先运行足以暴露本次错误的编译、格式与定向测试，再请求就绪评审。诊断编译失败、只读 review、讨论意图和澄清阻塞不以“全仓先绿”为前提。
检查失败时分析当前输出和相关实现；新修复重跑受影响检查，不盲目启动更多模型或反复重跑整个仓库。
纯 skill/文档修改走文档检查，不伪造 Scala 测试结果。

## 单一修改者

默认一个 Agent 完成开发与五视角自查。仅在明确授权协作且独立审查有收益时才分配任务；这一参考本身不授予委派权限。
若多人/多 Agent 协作，评审只读、修改归一个实施者，避免互相覆盖用户变更。编译测试不能替代对意图的审核，评审也不能代替编译器。

## 决策与阶段

可逆的小选择按现有约定解决。权限、公共契约或关键业务意图缺失时简短提问，继续不依赖答案的工作；不要凭空补规格。
优先在会话/现有变更规范记录问题。仅团队已有消费者或用户明确要求时使用 questions.md 等文件；不能把设想的 Suspension API 当作可调用工具。
长任务分为可验证的切片并保留回滚路径；不因阶段完成自动提交、推送、修改跨仓 pin 或部署。
