# 07. 确定性质量流水线与决策治理

用于长任务开发、重要版本交付、跨模块重构以及人机/多 Agent 协同流程。

## 一、 Bill Venners 铁律 #1：确定性工具优先 (Deterministic Code First)

> “凡是能用确定性程序（编译器、静态代码检查器、格式化脚本）解决的事情，绝对不要交给大模型或 AI Vibe 来猜测。”

1. **代码格式统一由工具裁决**：统一运行 `sbt scalafmtCheckAll` / `sbt scalafmtAll`；禁止在 Prompt 中向 AI 描述代码缩进和括号空格要求。
2. **类型与效应完全由编译器守卫**：开启 `-Wnonunit-statement`、`-Wvalue-discard`、`-Wunused:all`，将隐蔽 Bug 的拦截前置到编译阶段。
3. **文本与结构定位优先使用本地工具**：使用 `rg` / `rg --files` 以及 Metals 符号索引，杜绝大模型臆造不存在的文件或符号。

## 二、 绿门门禁准则 (The Green Gate)

任务的生命周期严格划分为两个阶段：

- **阶段 A：探索与诊断阶段 (Exploration & Diagnosis)**：
  允许代码处于编译未过或测试未绿的状态。Agent 可以自由定位错误日志、分析栈回溯、探究依赖关系，不强制要求必须先绿才能开始工作。
- **阶段 B：交付与合并就绪阶段 (Readiness & Delivery)**：
  在宣称“任务已完成”或发起合并请求前，**必须无条件通过本地绿门门禁**：
  1. `sbt compile`：0 错误，0 警告；
  2. `sbt scalafmtCheckAll`：格式检查 100% 通过；
  3. 定向与核心测试用例：100% 通过，无失败用例。

## 三、 决策账本机制 (Decision Ledger)

当在开发过程中遭遇以下情况时：
- 需求存在模糊或相互矛盾之处；
- 面临无法自动裁决的重大架构选型；
- 缺少关键业务不变量（如未授权状态的处理策略）；

**严禁凭空臆造架构决策（防止 Air France 447 自动驾驶陷阱）**。必须在 `questions.md`（或会话中）记录结构化的决策条目：

```markdown
### [DECISION-01] RAG 检索无命中时的回答策略
- **上下文**: `com.zyblw.domain.qa.QaAnswerProjector.scala#L85-L102`
- **问题**: 当本地知识库检索得分为 0 且用户开启了严格防护时，系统应当如何响应？
- **选项 A**: 直接返回硬编码的安全免责声明与拒答话术（确定性最高，无模型幻觉）。
- **选项 B**: 允许大模型基于自身预训练知识作答，但强制附加“未在站内命中证据”警示标。
- **推荐方案**: 建议采纳选项 A（符合医疗/高安全领域的 Fail-Closed 原则）。
```

在等待人类确认的同时，**继续推进不依赖该决策的其他独立子任务**，保持流水线持续生产。

## 四、 单一修改者与只读审计协作 (Single Adjudicator Pattern)

1. **职责分离**：
   - 审计角色（Reviewer）只具备只读权限，负责挖掘不变量破坏风险、安全漏洞并提供具体文件行号；
   - 实施角色（Adjudicator）负责收集所有审计意见，进行全局权衡，并单点落实代码修改与提交。
2. **杜绝修改冲突**：严禁多个 Agent 同时对同一份工作树执行写入，避免因并发覆盖产生幽灵代码或抹除人类意图。
